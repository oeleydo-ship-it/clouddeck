# SSH keys

Uplary authenticates to managed servers with **SSH public keys** you register in the control plane.

## Before provisioning

Add at least one key under **Account → SSH keys**:

| Method | Steps |
|--------|-------|
| **Generate** | Uplary creates a key pair; download the private key once and store it securely |
| **Upload** | Paste an existing public key (`ssh-ed25519` or `rsa-sha2-256` recommended) |

The selected key is installed on new Droplets and used for attach-by-IP bootstrap.

## Key selection

When creating a server or site, pick the key that matches the private key you retain for emergency manual SSH. Uplary does not expose generated private keys again after creation.

## Manual SSH access

You can still SSH directly:

```bash
ssh -i ~/.ssh/uplary root@203.0.113.10
```

Ensure your local private key corresponds to a public key on the server (`/root/.ssh/authorized_keys`).

## Rotation

1. Add a new SSH key in Uplary.
2. Re-provision is not required — use **Server → Operations** or manual SSH to append the new public key on the host.
3. Update server records if you replace the primary key used for remote operations.
4. Remove obsolete keys from the account and from `authorized_keys` on each host.

## Security notes

- Private keys generated by Uplary are shown once; the platform stores only the public half for provisioning.
- Restrict key permissions (`chmod 600`) on your workstation.
- Prefer Ed25519 over legacy RSA when both sides support it.
